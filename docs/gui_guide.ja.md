# GUI の手引き

> **v2.0.0 に向けて開発中です。** GUI は、今の安定版 v1.7.0 には入っていません。
> `gui` のコマンドも、まだ使えません。v2.0.0 の試しの版（TestPyPI の
> release candidate）から使えるようにする予定です。それまでは、
> [Getting Started from Garmin Export](getting_started_from_garmin_export.md)
> のとおりに、コマンドラインを使ってください。

[English](gui_guide.md)

GUI は、Garmin のエクスポート（Account Data Export）に対する一括処理（Run-All）を、
ブラウザの画面から行うためのものです。処理はコマンドラインと同じで、同じ入力と設定なら、
同じ出力を書き出します。データはすべて、このコンピューターの中で扱います。

## 用意するもの

- Python 3.11 以降で入れた、このパッケージ。GUI のために足す依存はありません。
- 同じコンピューターで動くブラウザ
- ZIP から展開した、Garmin のエクスポートのフォルダー。
  [Getting Started from Garmin Export](getting_started_from_garmin_export.md) の
  1 と 2 を見てください。
- 新しい出力のフォルダーを作るための空き容量

## GUI を起動する

```bash
garmin-running-data-normalizer gui
```

コマンドは、GUI のアドレスをターミナルに表示し、既定のブラウザで開きます。

- アドレスには、この起動だけの鍵が入っています。人に渡さないでください。
  鍵の無いページからは、GUI を使えません。画面にそう出たときは、
  ターミナルに表示されたアドレスを開いてください。
- GUI を使っている間は、ターミナルを閉じないでください。
- 画面の言語は、ブラウザの言語に合わせます。画面の下の「言語」で、
  英語と日本語を切り替えられます。選んだ言語は、そのタブの中だけで覚えます。

## 1. エクスポートのフォルダーを選ぶ

1. 「エクスポートのフォルダー（フルパス）」に、展開したエクスポートの
   フォルダーのフルパスを入れるか、「選ぶ…」で選びます。フォルダーを選ぶ
   画面には、フォルダーの名前だけが出ます。隠しフォルダーとリンクは出ません。
2. 「フォルダーを確かめる」を押します。これは `doctor --input` のコマンドと
   同じ確かめです。実行できるかどうかと、できないときに次にすることを出します。
   大きなエクスポートでは、確かめに時間がかかります。

フォルダーかタイムゾーンを変えると、確かめの結果は消えます。始める前に、
もう一度確かめてください。

## 2. 出力を決める

- 「出力を作る場所のフォルダー（フルパス）」：確かめが通ると、空のときは、
  エクスポートのフォルダーがある場所が入ります。このフォルダーは、すでにあって、
  書き込めることが必要です。GUI は、実行を始める前に書き込めるかを確かめます。
- 「新しく作る出力のフォルダーの名前」：`garmin-run-all-YYYYMMDD-HHMM`
  （年月日と時分）の形で、案が入ります。まだ無い名前にしてください。
  英数字なら 200 文字まで、日本語なら 66 文字までです。「.」で始めたり、
  `/` や `:` などの記号を入れたりはできません。
- 「日時に使うタイムゾーン」：既定は `Asia/Tokyo` です。`Europe/London` の
  ような IANA の名前で入れてください。
- 「外へ渡すための要約（External-safe Pack）も作る」：既定では作りません。
  コマンドラインの `--external-safe-pack` と同じ、アクティビティだけの要約です。
  渡す前に、中身を確かめてください。

Windows では、出力の場所と名前を短めにしてください。長いパスを有効にしていない
Windows では、パス全体が 260 文字までです。出力の中のファイルは、出力の
フォルダーのパスに、40 文字ほど足されます。パスが長すぎるときは、実行を
始める前に、GUI がそう知らせます。

出力のフォルダーは、実行が終わったときにはじめてできます。それまで一括処理は、
その隣の、隠れた作業用のフォルダーで作業します。

## 3. 実行する

- 「一括処理を始める」を押します。同時に実行できるのは 1 つだけです。
- 画面には、いまの段階と経過時間が出ます。FIT ファイルを読んでいる間は、
  読んだ件数が出ます。中身が同じファイルは 1 回だけ読みます。30 秒進まない
  ときは、そのことが出ます。大きなエクスポートでは時間がかかるので、
  そのまま待てます。
- 「取り消す」は、確認してから取り消します。終わる前に取り消した実行は、
  出力のフォルダーを作りません。取り消しが間に合わずに終わったときは、
  出力を残し、画面にそう出します。
- 強く止めたために、隠れた作業用のフォルダー（`.<名前>.run-all-…`）が
  出力の場所に残ったときは、画面にその名前が出ます。実行中でないことを
  確かめてから消してください。

## 4. 結果を読む

結果には、どう終わったかと、同じ結果のときにコマンドラインが返す終了コードが
出ます。

| 結果 | 終了コード | 意味 |
|---|---|---|
| `PASS` | 0 | 警告なしで終わりました |
| `PASS_WITH_WARNINGS` | 0 | 終わりました。警告を確かめてから、出力を使えます |
| `PARTIAL_SUCCESS` | 3 | 終わりました。アクティビティは使えますが、最後まで読めなかった FIT ファイルを除いています |

表には、データの種類ごとに、状態・件数・警告の数が出ます。

「出力の確かめ」は、実行のあとに自動で行います。`validate-handoff` と
`doctor --run-output` のコマンドと同じ確かめです。次のことを出します。

- 受け渡しの確かめ（データセットの数、データどうしのつながりの数、警告の数）
- 出力を使えるかどうかと、次にすること
- 警告の種類ごとの説明と、そのコード

「出力のフォルダーを表示する」は、macOS では Finder で、Windows では
エクスプローラーで、Linux では `xdg-open` が選ぶファイルのアプリで、
フォルダーを表示します。「START_HERE.md を開く」は、`.md` のファイルの
既定のアプリで開きます。出力は `START_HERE.md` から読み始めてください。
出力の説明が書いてあります。

実行のあとは、次の実行のための新しい名前の案が入ります。

## 5. 困ったときは、問い合わせ用の束を作る

「問い合わせ用の束を作る」は、出力のフォルダーの隣に
`<出力の名前>-support-bundle.zip` を作ります。`support-bundle` のコマンドと
同じです。

- 中身は、要約のファイル 6 個です。記録の行、場所（パス）、ファイル名、
  識別子、正確な時刻、位置の座標は入りません。どこにも送りません。
- 渡す前に、6 個のファイルをすべて確かめてください。中の件数から、
  どれくらい使っているかが分かることがあります。
- 同じ名前のファイルがあるときは、上書きしません。先に、移すか名前を
  変えてください。

束の中身は
[v1.4 Export Evidence and Diagnostics](v1_4_diagnostics.md#support-bundle) を、
問い合わせ先は [Support](../SUPPORT.md) を見てください。

## うまくいかないとき

うまくいかないときは、「起きたこと」「次にすること」「コード」を出します。
問い合わせるときは、コードを添えてください。エクスポートや出力は
添付しないでください。

| コード | 起きたこと | 次にすること |
|---|---|---|
| `PATH_NOT_ABSOLUTE` | フルパスではありません。 | フルパスで入れてください。Mac や Linux では `/` から、Windows では `C:\` のようなドライブから始まります。 |
| `FOLDER_NOT_READABLE` | フォルダーを開けません。 | Mac では、確認の画面で許可するか、システム設定の「プライバシーとセキュリティ」で許可してください。 |
| `ACTIVITIES_NOT_FOUND` | アクティビティが見つかりません。 | エクスポートの ZIP を展開したフォルダーを選んでください。 |
| `OUTPUT_EXISTS` | 同じ名前のフォルダーがすでにあります。 | 別の名前にしてください。 |
| `OUTPUT_NAME_INVALID` | その名前は使えないか、パスが長すぎます。 | 名前の決まりに合わせるか、短い名前にしてください。 |
| `OUTPUT_PARENT_NOT_WRITABLE` | 出力を作る場所に書き込めません。 | 別の場所を選ぶか、書き込みの権限を確かめてください。 |
| `OUTPUT_PATH_TOO_LONG` | 出力のパスが、Windows には長すぎます。 | ドライブの一番上に近い場所を選ぶか、名前を短くしてください。 |
| `INPUT_CHANGED` | 実行中に、エクスポートのファイルが変わりました。 | ほかのプログラムがフォルダーを変えていないときに、やり直してください。 |
| `OUTPUT_PUBLISH_FAILED` | 出力のフォルダーを書き出せませんでした。 | 空き容量と書き込みの権限を確かめてください。Windows では、出力の場所と名前を短くしてください。 |
| `HANDOFF_INVALID` | 出力のフォルダーが、実行で書いた内容と合いません。 | フォルダーを変えていなければ、コードを添えて知らせてください。 |
| `SUPPORT_BUNDLE_EXISTS` | 同じ名前の問い合わせ用の束が、すでにあります。 | 今あるファイルを、移すか名前を変えてください。 |

ほかのコードのときは、画面の「次にすること」に従ってください。

画面に「GUI が応答しません」と出たときは、ターミナルを閉じたなどの理由で、
GUI が止まっている可能性があります。同じコマンドで起動し直し、新しい
アドレスを開いてください。アドレスと鍵は、起動のたびに変わります。

## GUI を終える

- 画面の下の「終了」を押すか、ターミナルで `Ctrl+C` を押します。
- 実行中は「終了」を押せません。先に実行を取り消してください。`Ctrl+C` は、
  実行を取り消してから GUI を止めます。
- どのページも 10 分間 GUI を使わず、実行もしていないときは、GUI は
  自分で止まります。ブラウザのタブを閉じても、すぐには止まりません。

## プライバシー

- 一括処理の出力には、あなたの個人のデータが入っています。あなたが
  渡さない限り、このコンピューターの外には出ません。
- GUI は、ネットワークに何も送りません。利用の記録を集める仕組みも
  ありません。画面は、GUI の外から何も読み込みません。
- 外へ渡すための要約と問い合わせ用の束は、渡すために作るものですが、
  渡す前に中身を確かめてください。

[Security and Privacy Boundary](security_and_privacy_boundary.md) も
見てください。

## GUI の守り

- GUI は `127.0.0.1` だけで待ち受けるので、ほかのコンピューターからは
  つながりません。
- どの要求にも、この起動のアドレスにある鍵が要ります。同じコンピューターの
  ほかのプログラムやほかのアカウントは、鍵が無いと GUI を使えません。
- cookie は使いません。要求や場所（パス）を記録しません。

## キーボードとスクリーンリーダー

- すべての操作を、キーボードで行えます。フォーカスの位置は、いつも
  見えるようにしています。
- スクリーンリーダーは、実行の段階、止まっていること、取り消し、終わりを
  読み上げます。毎秒変わる件数は読み上げません。
- 実行が終わると、フォーカスは結果の見出しに移ります。ただし、画面の
  ほかの場所に移っていたときは、そのままにします。

## GUI とコマンドライン

GUI は、次のコマンドと同じ一括処理を行います。

```bash
garmin-running-data-normalizer run-all --input /path/to/export --output /path/to/new-output --timezone Asia/Tokyo
```

自動で動かすとき、Snapshot を使うとき、前に作った出力を確かめるときは、
コマンドラインを使ってください。

```bash
garmin-running-data-normalizer validate-handoff --input /path/to/output
garmin-running-data-normalizer doctor --run-output /path/to/output
garmin-running-data-normalizer support-bundle --run-output /path/to/output --output /path/to/support-bundle.zip
```
