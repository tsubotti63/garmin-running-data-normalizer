# Garmin Running Data Normalizer v1.3.0

Status: Prepared stable release source. Tag, GitHub Release, TestPyPI, and
Production PyPI publication require a separate Human authorization.

v1.3.0 adds optional daily Wellness/Metrics normalization while preserving the
stable v1.2.1 CLI, existing outputs, identity contracts, Snapshot behavior, and
privacy boundary.

## What's new

- Ten additive normalized datasets expand the Run-All catalog from 7 to 17
  datasets.
- Every added dataset has an explicit grain, stable key, schema, registry entry,
  Snapshot policy, QA/audit result, and Output Experience description.
- Relationship documentation distinguishes direct relationships from bounded
  same-day context and explicitly prohibits unsupported joins.
- Source-observation datasets retain every stable observation. Their daily QA
  summaries are derived views with no latest-wins selection.
- Lactate Threshold evidence is collected for audit but is not promoted to a
  stable normalized dataset.

## Supported datasets

The 17 normalized datasets are:

1. `activities`
2. `gear`
3. `activity_gear`
4. `personal_records`
5. `fit_sessions`
6. `fit_laps`
7. `activity_fit_links`
8. `hill_score_daily`
9. `endurance_score_daily`
10. `race_prediction_daily`
11. `sleep_daily`
12. `uds_daily`
13. `acute_training_load_daily`
14. `training_readiness_daily`
15. `vo2max_daily`
16. `hrv_daily`
17. `training_history_daily`

Health Status is not included. Lactate Threshold remains candidate/audit-only
and is not counted in the 17 normalized datasets.

## How to run

The existing one-shot interface is unchanged:

```bash
python -m garmin_running_data_normalizer run-all \
  --input /path/to/DI_CONNECT \
  --output workspace/run-all-v1-3
```

On Windows PowerShell:

```powershell
python -m garmin_running_data_normalizer run-all --input "C:\Garmin\DI_CONNECT" --output "C:\Garmin\Output\run-all-v1-3"
```

Activities remain required. Every added v1.3 family is optional. Absence is
recorded as `SKIPPED_NOT_PRESENT` and does not add a warning.

## Output changes

When matching source data is present, Run-All adds normalized JSON under
`normalized/`, aggregate dataset audit under `audit/`, and
`qa/daily_metrics_summary.json`. Hill and Endurance Score also have the derived,
non-canonical `analysis/performance_metrics_daily.csv` convenience projection.

The generated `START_HERE.md`, `DATASET_INVENTORY.md`, `ANALYSIS_HANDOFF.md`,
`ANALYSIS_CONTEXT.json`, and `SCHEMA_CATALOG.json` document the expanded catalog.
Existing output filenames and semantics are unchanged.

## Relationship and join guidance

The six existing explicit relationships remain unchanged. None of the added
Wellness/Metrics datasets is an Activity fact or gains a direct Activity
relationship. A documented `context_only` comparison may align separately
aggregated data by local calendar day, but it must not create Activity identity,
copy fields into Activity facts, or imply causality.

Consumers must use [Dataset Relationships](../dataset_relationships.md) as the
join authority. Date similarity, timestamp proximity, labels, and supplemental
source IDs do not independently authorize a join.

## Snapshot behavior

Snapshot Accumulation remains opt-in and preserves `missing_is_not_delete`.
Daily-state datasets use their declared day key; source-observation datasets use
immutable observation union; HRV is regenerated from retained FIT evidence.
Stable-key conflicts fail closed or remain explicit review evidence according
to the dataset contract. No automatic deletion or latest-wins fallback is added.

## Backward compatibility

- CLI commands and arguments: unchanged.
- Existing dataset IDs and fixed output paths: unchanged.
- Existing stable keys: unchanged.
- Exit-code meanings: unchanged.
- Existing package imports: unchanged.
- Six existing explicit relationship contracts: unchanged.
- Privacy and local-processing boundary: unchanged.
- New outputs: additive and optional.

## Known limitations

- Lactate Threshold remains candidate/audit-only. Stable promotion is deferred
  until machine identity, units, timezone, heart-rate authority, FTP/power
  authority, and public field/type rules are finalized. Fail-closed behavior is
  retained.
- HRV Daily is `analysis_reference_only`; it is not a daily coaching Source of
  Truth and must not be treated as equivalent to Health Status HRV.
- Health Status is deferred and is not a supported v1.3 dataset.
- Direct Activity relationships for new Wellness/Metrics datasets are
  `not_yet_defined`; same-day analysis is context only.
- Hosted processing, Garmin authentication, weather integration, automatic
  upload, and medical/coaching interpretation remain outside scope.

See [Known Limitations](../known_limitations.md) for the complete boundary.

## Upgrade instructions

Before publication, install the reviewed checkout or built artifact only in a
release-validation environment. After the separate Production PyPI gate is
complete, the intended upgrade command is:

```bash
python -m pip install --upgrade garmin-running-data-normalizer==1.3.0
```

No data migration is required for one-shot Run-All users. Use a new output
directory for each run. Snapshot users should verify the store, register only a
confirmed complete Export, build a new canonical output, and keep the previous
verified output until the new result passes review.

## Validation summary

The prepared source is gated by the full pytest and unittest suites,
bootstrap/platform/static/schema/registry checks, Snapshot lifecycle tests,
repeated deterministic Synthetic Run-All, Output Experience and relationship
validation, privacy scanning, wheel and source-distribution builds, isolated
artifact installs, and Ubuntu/Windows CI. Exact final results and artifact
hashes are recorded in the ignored Release Preparation Pack before Product
authorization.

Private full Run-All can still stop at the pre-existing Activity/Gear orphan
relationship invariant. That fail-closed condition is not introduced by v1.3
and does not authorize publication of private input or output evidence.
