# Garmin Running Data Normalizer v1.4.1

These are the release notes for the v1.4.1 FIT correctness and metadata-file
patch release. Version `1.4.1` was published from the release-ready main source
after the v1.4.1 tag, GitHub Release, and Production PyPI publication gates.
The current stable release is v1.5.0.

## Fixed

- FIT session `sport` and `sub_sport` now use FIT profile names. The previous
  tables used the wrong codes, so indoor cycling became `treadmill_running`,
  mountain biking became `trail_running`, and real treadmill and trail runs had
  no sub-sport. The sub-sport no longer renames the sport.
- FIT-derived HRV now uses the same container checks as FIT sessions (size,
  header, truncation, chaining, header CRC, and file CRC). A FIT file that
  fails them no longer contributes HRV values.
- AppleDouble `._*` files, including those under `__MACOSX/`, in an Export
  folder no longer make Run-All, `normalize-*`, or `doctor --input` fail or
  report incomplete FIT input. `.DS_Store` and `Thumbs.db` are ignored by the
  same rule.
- The same metadata files in a completed output no longer make
  `validate-handoff`, `doctor --run-output`, or `support-bundle` fail. Any
  other undeclared file still fails.

## Output changes

Rerun Run-All after upgrading. Compared with v1.4.0 output from the same
Export:

- FIT session `sport` / `sub_sport` values change, for example:
  - indoor cycling: `treadmill_running` / `treadmill_running` → `cycling` /
    `indoor_cycling`
  - mountain biking: `trail_running` / `trail` → `cycling` / `mountain`
  - road cycling: `cycling` / `street` → `cycling` / `road`
  - treadmill run: `running` / null → `running` / `treadmill`
  - trail run: `running` / null → `running` / `trail`
  - pool swim: `"5"` / null → `swimming` / `lap_swimming`
  - training (sport code 10): `strength_training` → `training`; a sub-sport
    such as `strength_training` is now kept, so filter strength sessions by
    `sub_sport`
  - sport code 0: `"unknown"` → `generic`; sub-sport code 0: null → `generic`
- Activity/FIT links: sessions whose sport was misnamed, such as cycling and
  swimming, can now count as `compatible_sport`, so additional
  evidence-qualified links may appear.
- `hrv_daily` can contain fewer days when a FIT file fails the container
  checks. The HRV audit `parse_status_counts` can now include `bad_file_crc`,
  `bad_header_crc`, `unsupported_chained`, and `truncated`.
- Outputs record `product_version` `1.4.1`. `validate-handoff`,
  `doctor --run-output`, and `support-bundle` accept an output that contains
  `diagnostics/` only when the installed version produced it, so rerun Run-All
  for outputs produced by v1.4.0.

## Compatibility

- The 17-dataset, 212-field, 6-relationship inventory, stable keys, and output
  paths are unchanged.
- Snapshot semantics are unchanged, including ZIP member selection, content
  identities, and re-registration.
- The Product exit mapping remains `PASS -> 0`,
  `PASS_WITH_WARNINGS -> 0`, `PARTIAL_SUCCESS -> 3`, and `Fatal -> 2`.
- `PARTIAL_SUCCESS` / exit 3 is a completed result with bounded FIT exclusions,
  not a Fatal result.
- Local dates and times are still computed in the IANA `Asia/Tokyo` timezone;
  see [Known Limitations](../known_limitations.md#local-dates-and-times).

## Install

```bash
python -m pip install garmin-running-data-normalizer==1.4.1
garmin-running-data-normalizer --version
```
