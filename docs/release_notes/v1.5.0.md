# Garmin Running Data Normalizer v1.5.0

These are the release notes for the v1.5.0 Snapshot and output hardening
release. Version `1.5.0` is the current stable release, published from the
release-ready main source after the v1.5.0 tag, GitHub Release, and Production
PyPI publication gates.

## Changed

- New Snapshot Stores are owner-only on Unix-like systems, regardless of the
  umask: directories `0700` (including missing parent directories created for
  a new store), immutable blobs, manifests, and inventories `0400`, and other
  files `0600`. `normalize-activities` creates a new output directory as
  `0700` with `0600` files. Existing stores and directories keep their
  permissions; tighten an older store with `chmod -R go-rwx <store>`. Windows
  ignores these modes.
- `Thumbs.db` inside a ZIP file is skipped by the same operating-system
  metadata rule as Export folders and Snapshot folder input.
- Snapshot Sleep keeps every Sleep field that Run-All reads. The direct
  duration aliases `durationInSeconds` and `sleepDuration`, the snake_case
  stage fields (`deep_sleep_seconds`, `light_sleep_seconds`,
  `rem_sleep_seconds`, `awake_sleep_seconds`), and the top-level
  `overallScore` and `sleepScore` were dropped before.
- `support-bundle` accepts Run Quality produced by `1.x` releases from `1.4`
  onward, so it works with v1.5.0 outputs; the check previously matched only
  `1.4.x`.

## Fixed

- `snapshot run-all` no longer returns `null` for Sleep values that Run-All on
  the same Export reads from those fields.
- When Snapshots disagree for the same stable key, `snapshot build-input` and
  `snapshot run-all` report counts by dataset and conflict type, for example
  `sleep_daily same_stable_key_different_public_value=1`, without dates, keys,
  or values.
- A lock left by an interrupted `snapshot register` is reported with the lock
  file name, its recorded process ID, and the recovery step: confirm that no
  other snapshot command is running, delete `.single-writer.lock`, and rerun
  `snapshot register` with the same Export or another complete Export.

## Output and Snapshot changes

Rerun Run-All after upgrading. Compared with v1.4.1:

- One-shot Run-All output from the same Export is unchanged apart from
  `product_version` `1.5.0` and the digests that include it.
- Existing Snapshot Stores load and verify as before, including Stores with
  ZIP files that contain `Thumbs.db`. A Store whose Sleep rows use none of the
  added fields builds and gives the same `snapshot run-all` output apart from
  the version.
- A new registration of a ZIP that contains `Thumbs.db` receives a different
  Snapshot content identity than in v1.4.1. Re-registering such an Export with
  its original label fails, and a new label adds another Snapshot; do not
  re-register Exports already registered with an earlier version.
- When Sleep rows use the added fields, `snapshot run-all` now reports their
  values. Snapshot Sleep stops when Exports differ for one `calendarDate` in a
  kept field, including a field present in one Export and absent in another,
  so a Store that v1.4.1 could build can stop with v1.5.0.
- `validate-handoff`, `doctor --run-output`, and `support-bundle` accept an
  output that contains `diagnostics/` only when the installed version produced
  it, so rerun Run-All for outputs produced by v1.4.1 or earlier.

## Compatibility

- The 17-dataset, 212-field, 6-relationship inventory, stable keys, and output
  paths are unchanged.
- The Snapshot lifecycle contract and policy registry versions remain `v1.0`;
  existing Stores load and verify without migration.
- The Product exit mapping remains `PASS -> 0`,
  `PASS_WITH_WARNINGS -> 0`, `PARTIAL_SUCCESS -> 3`, and `Fatal -> 2`.
- `PARTIAL_SUCCESS` / exit 3 is a completed result with bounded FIT exclusions,
  not a Fatal result.
- Local dates and times are still computed in the IANA `Asia/Tokyo` timezone;
  see [Known Limitations](../known_limitations.md#local-dates-and-times).

## Install

```bash
python -m pip install garmin-running-data-normalizer==1.5.0
garmin-running-data-normalizer --version
```
