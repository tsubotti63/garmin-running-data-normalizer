# Garmin Running Data Normalizer v1.7.0

These are the release notes for the v1.7.0 FIT running dynamics release.
Version `1.7.0` is the current stable release, published from the
release-ready main source after the v1.7.0 tag, GitHub Release, and Production
PyPI publication gates.

## Added

`fit_sessions` and `fit_laps` include six FIT running-dynamics averages, read
from the FIT session and lap messages and scaled as defined by the FIT profile:

| Field | FIT session / lap field | Unit |
|---|---|---|
| `avg_vertical_oscillation_mm` | `avg_vertical_oscillation` (89 / 77) | millimetre |
| `avg_stance_time_ms` | `avg_stance_time` (91 / 79) | millisecond |
| `avg_stance_time_percent` | `avg_stance_time_percent` (90 / 78) | percent |
| `avg_stance_time_balance_percent` | `avg_stance_time_balance` (133 / 119) | percent |
| `avg_vertical_ratio_percent` | `avg_vertical_ratio` (132 / 118) | percent |
| `avg_step_length_mm` | `avg_step_length` (134 / 120) | millimetre |

- `fit_sessions` always contains the six fields, with `null` when the FIT
  session does not record them. `fit_laps` contains them when the FIT lap
  message defines them, like the other lap fields.
- `avg_stance_time_balance_percent` is the recorded FIT
  `avg_stance_time_balance` value, in percent, and is not converted to a left
  or right side.
- `SCHEMA_CATALOG.json` describes the new fields as numbers with the units
  `millimetre`, `millisecond`, and `percent`.

`analysis/activities.csv` appends ten columns after `lap_count`, so the
running dynamics and other per-activity aggregates are available in the
analysis entry point:

- `elapsed_duration_sec` and `moving_duration_sec`: Garmin's `elapsedDuration`
  and `movingDuration` (the whole elapsed time including pauses, and the time
  Garmin counted as moving), converted from milliseconds like `duration_sec`.
- `fit_avg_vertical_oscillation_mm`, `fit_avg_stance_time_ms`,
  `fit_avg_stance_time_percent`, `fit_avg_stance_time_balance_percent`,
  `fit_avg_vertical_ratio_percent`, `fit_avg_step_length_mm`,
  `fit_total_ascent_m`, and `fit_total_descent_m`: values from the FIT session
  joined to the activity through an explicit `activity_fit_links` row. Links
  are never inferred from timestamp proximity, and the columns are empty
  without an explicit link or when the FIT value is null.
- The table remains a derived projection of `activities`. The `activities`
  relationship metadata in `ANALYSIS_CONTEXT.json` and `SCHEMA_CATALOG.json`
  declares the derived and joined columns.

## Not included

- Garmin's activity export also contains running-dynamics values under other
  names. The product uses the FIT values and does not read those activity-list
  values.
- The External-safe Pack and the Support Bundle do not include the new fields
  or columns.

## Output changes

Rerun Run-All after upgrading. Compared with v1.6.0:

- Records in `normalized/fit_sessions.json` gain the six fields, and records in
  `normalized/fit_laps.json` gain them when the FIT lap message defines them.
  Values in the existing fields are unchanged.
- `SCHEMA_CATALOG.json` lists 224 fields instead of 212.
- `analysis/activities.csv` gains ten columns after `lap_count`; the existing
  15 columns keep their positions and values. `ANALYSIS_CONTEXT.json` and
  `SCHEMA_CATALOG.json` add the `derived_columns` and `joined_columns`
  declarations, and `START_HERE.md` and `ANALYSIS_HANDOFF.md` describe the
  `fit_*` columns.
- For an Export with FIT files, the digests that cover `fit_sessions` and
  `fit_laps` also change: `records_sha256` in `run_manifest.json` and
  `qa/dataset_summary.json`, and the output digests in
  `diagnostics/run_quality.json`; the run-level digests in `run_manifest.json`
  and `run_summary.json` change with them. No QA or diagnostic verdict
  changes.
- Invalid FIT values (`0xFFFF`) in the new fields become `null` and are counted
  in the FIT `invalid_sentinel_count` and `invalid_sentinel_counts` (in
  `audit/fit_audit.json`, `run_summary.json`, and `qa/dataset_summary.json`).
  These counts can grow when a FIT file defines the new fields without valid
  values; warnings, the run status, and diagnostics are unchanged.
- Other datasets, `analysis/performance_metrics_daily.csv`, and other audit
  records from the same Export are unchanged apart from `product_version`
  `1.7.0` and the digests that include it.
- `validate-handoff`, `doctor --run-output`, and `support-bundle` accept an
  output that contains `diagnostics/` only when the installed version produced
  it, so rerun Run-All for outputs produced by v1.6.0 or earlier.

## Compatibility

- The 17 datasets, 6 relationships, stable keys, and output paths are
  unchanged; the field inventory grows from 212 to 224.
- The Snapshot lifecycle contract and policy registry versions remain `v1.0`.
  FIT files are kept as files in the Snapshot Store, so existing Stores load
  and verify without migration, and `snapshot run-all` reports the new fields.
- The Product exit mapping remains `PASS -> 0`,
  `PASS_WITH_WARNINGS -> 0`, `PARTIAL_SUCCESS -> 3`, and `Fatal -> 2`.
- `PARTIAL_SUCCESS` / exit 3 is a completed result with bounded FIT exclusions,
  not a Fatal result.
- CLI options are unchanged; `--timezone` from v1.6.0 applies as before.

See [Known Limitations](../known_limitations.md#fit) and the
[Output Contract](../output_contract.md).
