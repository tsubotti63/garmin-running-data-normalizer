# Garmin Running Data Normalizer v2.0.0

These are the release notes for v2.0.0, the release that adds a local GUI and
changes how problems in the data are handled. Version `2.0.0` was published
from the release-ready main source after the v2.0.0 tag, GitHub Release, and
Production PyPI publication gates. It is the first release of the stable `2.x`
family. The current stable release is v2.1.0.

## Added: the local GUI

- `garmin-running-data-normalizer gui` serves a page for the browser of the
  same computer on `127.0.0.1` only, opens it, and prints its address, which
  holds the key of this launch. Every request needs that key. The GUI sends
  nothing to the network, uses no cookie, and loads nothing from outside this
  app.
- One page with four numbered boxes, in English and Japanese:
  1. the Export, the downloaded ZIP file or its folder, chosen with the window
     of the system;
  2. the Snapshots: the Snapshot Store, and whether to import this Export;
  3. the output;
  4. normalizing, with the results by step and by dataset, the check of the
     output, and the Support Bundle.
- Three ways to normalize: import this Export into the store and normalize
  all Snapshots together (the default), normalize this Export only, and
  normalize the Snapshots again without importing.
- The page also gives:
  - the outputs that earlier runs made;
  - the change since the output before;
  - a help panel;
  - work with the keyboard and screen readers.
- With `--create-shortcut`, `gui` first makes an icon that starts the GUI,
  with the picture of this app:
  - on macOS, `Garmin Running Data Normalizer.command` on the desktop;
  - on Windows, shortcuts on the desktop and in the Start menu.
  - Linux has no icon.
- The [GUI Guide](../gui_guide.md) gives one line for macOS and one for
  Windows PowerShell. Each line makes a virtual environment, installs this app
  in it, makes the icon, and opens the GUI.
- The GUI runs the same processing as the CLI: for the same input and options,
  it writes the same output.
- Exit codes of `gui`:
  - 0 after the Quit button, or after `Ctrl+C` without a run;
  - 130 when `Ctrl+C` stopped a run;
  - 2 when the icon cannot be made, with an `ERROR [SHORTCUT_…]` line.

## Changed: problems in the data

- Runs no longer stop on problems in the data.
  - A file or row that cannot be used is left out with a warning, and the run
    ends with `PARTIAL_SUCCESS` (exit 3).
  - Values that disagree are kept empty and marked in `disagreeing_fields`,
    with every value in the audit records.
  - No value is dropped or chosen silently.
  - Runs still stop for safety, for a folder that is not an Export, and for
    an input that mixes Exports or accounts.
- `--input` takes the downloaded Export ZIP file as it is, as well as the
  folder extracted from it.
- Every `ERROR` line ends with the next step of its code, and some stops have
  codes of their own.
- New stops:
  - an input that holds different Exports or more than one account;
  - a folder that this app is not allowed to open;
  - a folder for the output that does not exist;
  - an output name that not every system accepts.
- A JSON file nested more than 256 deep is a file that cannot be read on every
  version of Python.
- `Ctrl+C` ends every command with exit 130.
- New command: `snapshot unlock --store <store> --confirm-no-other-command`.
  It removes the lock file that a stopped registration left.

The [Migration Notes](../migration_notes.md#v171-to-v200) list every change
with its codes.

## Output changes

- The 17 datasets hold 247 fields (224 in v1.7.1).
  - Every row has `disagreeing_fields`.
  - New fields: `start_time_source`, `sleep_day_source`,
    `sleep_duration_source`, `sub_sport_code`,
    `activity_relationship_reason`, and `gear_relationship_reason`.
- Four audit records are added: `audit/activities.json`, `audit/gear.json`,
  `audit/activity_gear.json`, and `audit/personal_records.json`.
- `run_manifest.json` lists the files left out and the files that a run does
  not read.
- `run_all_version` is 2.
- New warning codes: `VALUES_DISAGREE`, `VALUES_UPDATED`,
  `RECORDS_NOT_IN_LATEST_SNAPSHOT`, `INPUT_DUPLICATE_SOURCES`,
  `DATA_FILE_LEFT_OUT`, `DATA_ROW_LEFT_OUT`, `DATA_VALUE_INVALID`,
  `DATA_TEXT_REPAIRED`, `RELATIONSHIP_UNRESOLVED_INVALID_LINK`, and
  `ACTIVITY_FIT_LINK_AMBIGUOUS`.

Rerun Run-All and `snapshot run-all` into new folders after upgrading; earlier
outputs are not converted. `validate-handoff`, `doctor --run-output`, and
`support-bundle` of v2.0.0 refuse an output of v1.7.1 with
`OUTPUT_OTHER_VERSION`, and those of v1.7.1 refuse an output of v2.0.0.

## Compatibility

- The 17 datasets and their stable keys are unchanged; ten fields become
  nullable.
- Snapshot Stores need no migration:
  - The Snapshot lifecycle contract and policy registry stay `v1.0`, and the
    store format stays 1. Existing Snapshot Stores load and verify without
    migration.
  - v1.7.1 still reads a store that v2.0.0 registered to. It leaves out,
    without a warning, a ZIP file inside an Export that v2.0.0 stored without
    its members because it could not be read.
- The Product exit mapping stays `PASS -> 0`, `PASS_WITH_WARNINGS -> 0`,
  `PARTIAL_SUCCESS -> 3`, and `Fatal -> 2`, with 130 for `Ctrl+C`.
- `PARTIAL_SUCCESS` / exit 3 is a completed result: the Activities are valid
  and a file or row was left out, which the warnings name. It is not a Fatal
  result.
- CLI commands and options are the same, apart from `gui` and `snapshot
  unlock`. For `run-all`, `snapshot run-all`, `snapshot build-input`, and
  `normalize-activities`, the folder for the output must exist.
- Python 3.11 or later, and no new runtime dependency.

## How it was checked

- Five release candidates, 2.0.0rc1 through 2.0.0rc5, were published on
  TestPyPI only and checked before this release (see
  [Release Readiness](../release_readiness.md)).
- On macOS, each release candidate was checked with synthetic data and with
  the maintainer's own Export. For the maintainer's Export, only counts and
  whether the files were the same were compared, and nothing from it is
  published.
- 2.0.0rc1 and 2.0.0rc4 were also checked on one physical Windows 11 x64
  machine.
- The GUI was checked by hand on macOS with Google Chrome, Safari, the
  keyboard, and VoiceOver.
- In place of a first-time user, whom no one could be found to be, new AI
  sessions that had never seen the GUI used it with synthetic data, and later
  read the guides. An AI session does not hesitate as a person does, so this
  check is weaker than a check by a person.
- The CI runs the tests with Python 3.11 on Linux and Windows and with Python
  3.15 on Linux, macOS, and Windows.

None of this establishes that every system and environment works.

See [Known Limitations](../known_limitations.md) and the
[GUI Design](../gui_design.md).

## Install

```bash
python -m pip install garmin-running-data-normalizer==2.0.0
garmin-running-data-normalizer --version
```

To install the GUI with its icon, use the line in
[What you need](../gui_guide.md#what-you-need) of the GUI Guide.
