# Garmin Running Data Normalizer v2.0.1

These are the release notes for v2.0.1, which fixes small things of the page
of the local GUI and of the GUI Guide. Version `2.0.1` is the current stable
release, published from the release-ready main source after the v2.0.1 tag,
GitHub Release, and Production PyPI publication gates. The processing, the
outputs, the command line, and the Snapshot Store are those of v2.0.0.

## Fixed: the page of the GUI

- **Quit** asks first. The question, **Quit this app?**, is in the bar at the
  bottom of the page, with **Quit this app** and **Keep using it**; Escape
  also keeps the app. While the app stops, the bar says **Quitting this
  app…**. When it has stopped, the bar says so, and the line at the top says
  how to start it again from the icon or with the command. The buttons that
  need the app cannot be pressed then; the language and the help stay usable.
- The bar at the bottom of the page stays on the screen while the page
  scrolls.
- After a run, a line under **Run normalization** says what pressing it again
  does: it normalizes again with the name in the name field, and the output of
  the run stays as it is. When the run imports into the Snapshots, the line
  adds that the same Export is not imported twice.
- When **Normalize this export only (no import)** is chosen, the Snapshot box
  no longer says that a Snapshot Store will be made there.
- The help marks **Read the result** as done only once `START_HERE.md` is
  opened from the page; until then, it is the current step.
- The hint of the box that runs says to open the output with **Show the output
  folder**, and the help of the timezone says that a name can also be chosen
  from the list.
- When the computer could not open a folder or a file, the English page says
  "This computer could not open it."

## Changed: the GUI Guide

The GUI Guide (English and Japanese) answers what a first reading of the guide
of v2.0.0 asked:

- **What you need** gives the installation in numbered steps: check Python,
  install it when it is missing or older (macOS, Windows, and an older
  Python), open the terminal again, and run the one line. It says what the
  developer-tools window of macOS and "is not recognized" of Windows mean.
- A new part says how to tell the project when the GUI does not open, field by
  field of the bug report, with no real data, path, or screenshot.
- A new part says what to do when the icon could not be made, by the code that
  the line prints.
- The parts about updating, going back to an open GUI, stopping the GUI, and
  removing this app say more: how to see the installed version, what the page
  says when its address no longer works, and which places to remove.
- The table of a line that stops names the lines that Windows PowerShell 5.1
  shows when the line for macOS is pasted there, and says to run the line for
  Windows PowerShell instead.

The guide describes the page of v2.0.1.

## Output changes

Outputs record `product_version` `2.0.1`, and the digests that include it
change with it. The datasets, fields, audit records, and warning codes are
those of v2.0.0.

`validate-handoff`, `doctor --run-output`, and `support-bundle` of v2.0.1
stop for an output of v2.0.0 with `OUTPUT_OTHER_VERSION`, as each version does
for the outputs of other versions, and the GUI shows the change since an
earlier output only for an output of the same version. Check an output of
v2.0.0 with v2.0.0, or rerun Run-All into a new folder.

## Compatibility

- The 17 datasets, 247 fields, stable keys, and output paths are unchanged.
- Snapshot Stores need no migration. The Snapshot lifecycle contract and
  policy registry stay `v1.0`, and the store format stays 1.
- The Product exit mapping stays `PASS -> 0`, `PASS_WITH_WARNINGS -> 0`,
  `PARTIAL_SUCCESS -> 3`, and `Fatal -> 2`, with 130 for `Ctrl+C`.
- `PARTIAL_SUCCESS` / exit 3 is a completed result: the Activities are valid
  and a file or row was left out, which the warnings name. It is not a Fatal
  result.
- CLI commands and options are unchanged.
- Python 3.11 or later, and no new runtime dependency.

See the [Migration Notes](../migration_notes.md#v200-to-v201).

## How it was checked

- The release candidate 2.0.1rc1 was published on TestPyPI only and checked
  before this release (see [Release Readiness](../release_readiness.md)): on
  macOS, its installation, the line of the guide, and the page by hand with
  synthetic data, and on one physical Windows 11 x64 machine, the line of the
  guide, which installed it and made the icons, and the two ways to normalize
  on the page.
- The CI runs the tests with Python 3.11 on Linux and Windows and with Python
  3.15 on Linux, macOS, and Windows.

## Install

```bash
python -m pip install garmin-running-data-normalizer==2.0.1
garmin-running-data-normalizer --version
```

To install the GUI with its icon, use the line in
[What you need](../gui_guide.md#what-you-need) of the GUI Guide. To update an
installed v2.0.0, follow
[Update to a new version](../gui_guide.md#update-to-a-new-version), which
stops the GUI first.
