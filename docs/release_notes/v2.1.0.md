# Garmin Running Data Normalizer v2.1.0

These are the release notes for v2.1.0, which adds a way to look at the
numbers of an output: the view page of the local GUI, and the `series`
command. Version `2.1.0` is the current stable release, published from the
release-ready main source after the v2.1.0 tag, GitHub Release, and Production
PyPI publication gates. The processing, the outputs, and the Snapshot Store
are those of v2.0.1.

## Added: the view page

- **View this output** in box 4 after a run, or **Open the view page** in the
  bar at the bottom of the page, opens the view page in the next tab. When it
  is open already, its tab comes to the front. **Go to the normalization page**
  at the top of the view page brings the page of the GUI to the front.
- The view page shows the items that you choose on the item shelf, such as
  distance, resting heart rate, and VO2 Max, in panels on one time axis. The
  first time, it shows these three; after that, the GUI remembers the items,
  and whether the shelf is open.
- **Period** (**All time**, the last 10, 5, 3, or 1 years, or **Custom
  range…**), **Group by** (**Auto**, **Day**, **Week**, **Month**, or
  **Year**), and **Activity types counted** apply to every panel. The last
  years end on the last day of the output, not on today. **Activity types
  counted** applies to the training and running-form items only.
- The overview below the panels shows an item over all time: dragging across
  it chooses the period. **Full screen** shows only the charts and the
  overview; **Back (Esc)** or Escape goes back.
- Each panel can be enlarged, moved up or down, or removed, and shown as a
  table. The second line of a panel gives how many periods have a record, and
  the smallest, the largest, and the last value.
- The view page reads the output and changes nothing in it. It does not say
  what causes what, or what to do. It opens only outputs made by this version.

## Added: `series`

`series` writes the numbers that the view page shows to a new CSV file, for a
spreadsheet or another tool. It takes the same items, period, grouping, and
activity types as the view page, and prints by item what the numbers leave
out, as counts. See
[Optionally write the numbers to a CSV file](../getting_started_from_garmin_export.md#8-optionally-write-the-numbers-to-a-csv-file)
and [Additive v2.1 series CSV](../output_contract.md#additive-v21-series-csv).

## Added: the colors of the page

**Appearance** in the bar at the bottom of both pages chooses **Match this
computer**, **Light**, or **Dark**. **Match this computer** follows the colors
that the browser reports, which in some browsers differ from the setting of
the computer. The GUI remembers **Light** or **Dark**.

## Changed

- The GUI stops by itself when none of its pages has been open for an hour,
  instead of 10 minutes, unless a run is going on.
- The GUI Guide (English and Japanese) describes the view page, with a picture
  of it, the colors, what the GUI remembers, and the hour.

## Fixed: two races of 2.0.x

- Two changes of the settings at the same time, in the same GUI, could lose
  one of them, for example when a run ended while the tips were switched. A
  change now waits for the other one. Two GUIs of two processes that write at
  the same time are not covered, as before.
- The list of earlier outputs kept a mark that moved at every request of the
  list, so that a second tab that asked for the list made the numbers that the
  first tab had been given refused with `OUTPUT_LIST_CHANGED`, even for the
  same outputs. The mark now moves only when the outputs of the list change; a
  list that changed still refuses the numbers given before.

## Output changes

Outputs record `product_version` `2.1.0`, and the digests that include it
change with it. The datasets, fields, audit records, and warning codes are
those of v2.0.1.

`validate-handoff`, `doctor --run-output`, `support-bundle`, and `series` of
v2.1.0, and the view page, stop for an output of v2.0.1 with
`OUTPUT_OTHER_VERSION`, as each version does for the outputs of other
versions; for an output of v1.3, which passes the checks, `series` and the
view page stop with `SERIES_OUTPUT_OTHER_VERSION`. The GUI shows the change
since an earlier output only for an output of the same version. To look at
the numbers of an earlier output, normalize its Export again with v2.1.0 into
a new folder.

## Compatibility

- The 17 datasets, 247 fields, stable keys, and output paths are unchanged.
- Snapshot Stores need no migration. The Snapshot lifecycle contract and
  policy registry stay `v1.0`, and the store format stays 1.
- The Product exit mapping stays `PASS -> 0`, `PASS_WITH_WARNINGS -> 0`,
  `PARTIAL_SUCCESS -> 3`, and `Fatal -> 2`, with 130 for `Ctrl+C`.
- `PARTIAL_SUCCESS` / exit 3 is a completed result: the Activities are valid
  and a file or row was left out, which the warnings name. It is not a Fatal
  result.
- The CLI adds `series`; the other commands and options are unchanged.
- The settings file of the GUI stays format 1. v2.0.1 leaves out the keys that
  it does not know whenever it writes the file: after that, v2.1.0 has
  forgotten the colors and the items of the view page.
- Python 3.11 or later, and no new runtime dependency.

See the [Migration Notes](../migration_notes.md#v201-to-v210).

## How it was checked

- The release candidate 2.1.0rc1 was published on TestPyPI only and checked
  before this release (see [Release Readiness](../release_readiness.md)):
  - on macOS: its installation from TestPyPI, and by hand in Safari and
    Chrome with a synthetic Export of fifteen and a half years, the view page,
    its overview and full screen, and quitting from it;
  - with the maintainer's own real Export, on macOS, by a script that recorded
    only whether each check passed;
  - on one physical Windows 11 PC, with Windows PowerShell 5.1, Python 3.14.5,
    Microsoft Edge, and the display at 150%: the line of the guide for Windows
    PowerShell, with the index of TestPyPI, which installed it and made the two
    icons; a synthetic Export normalized on the page; the view page, with its
    tabs, overview, full screen, and colors; quitting from the view page; and
    removing this app;
  - by two new AI sessions with no context: one read the draft of the part of
    the GUI Guide about the view page, and one used the view page from its
    screen only and found the answer to a question.
- The CI runs the tests with Python 3.11 on Linux and Windows and with Python
  3.15 on Linux, macOS, and Windows.

## Install

```bash
python -m pip install garmin-running-data-normalizer==2.1.0
garmin-running-data-normalizer --version
```

To install the GUI with its icon, use the line in
[What you need](../gui_guide.md#what-you-need) of the GUI Guide. To update an
installed v2.0.1, follow
[Update to a new version](../gui_guide.md#update-to-a-new-version), which
stops the GUI first.
